set_velocity(vx, vy, omega)¶

Command a holonomic body-frame velocity on the three-wheel swerve.

Robot / IMU frame: +X forward, +Y left, yaw positive counter-clockwise. Translation is in m/s; omega is in rad/s. Drive motors are commanded in rad/s via motor_velocity = wheel_linear_speed / wheel_radius.

Inverse kinematics for module i at (x_i, y_i) from config.wheel_positions (center, right, left; not assumed equal):

wheel_vx = vx - omega * y_i wheel_vy = vy + omega * x_i

Steering motors are clockwise-positive (0 = forward, +pi/2 = right), so the steer command is -atan2(wheel_vy, wheel_vx) folded into [-pi/2, +pi/2]. Headings outside that range reverse the drive motor instead of clamping. Between (angle, speed) and (angle ± pi, -speed), the representation closest to the wheel’s current steer angle is used. The last command is kept unless the other equivalent is closer by more than 20 deg, so live encoder noise does not chatter between ±90. When strict steering is off, each drive speed is also scaled by max(0, cos(steer_error)) so a large heading change does not shove the chassis sideways while the module is still rotating.

If any drive motor would exceed its configured max_velocity, all three wheel speeds are scaled by the same factor so the commanded body-velocity direction is preserved.

Parameters:

  • vx (float) – Robot-frame X velocity in m/s. +X is forward.

  • vy (float) – Robot-frame Y velocity in m/s. +Y is left.

  • omega (float) – Yaw rate in rad/s. Positive is counter-clockwise.

Return type:

None

set_strict_directions(value)¶

Wait for steering to reach the commanded heading before spinning the drive wheels.

True (default) matches the original behavior: drive motors are held at 0 until all turning motors are within rotation_tolerance of their targets. False applies drive velocity immediately so small joystick heading changes do not stop the robot.
