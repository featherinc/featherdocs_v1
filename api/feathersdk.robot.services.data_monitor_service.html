class feathersdk.robot.services.data_monitor_service.MonitorBinaryFileWriter(monitor_dir, max_file_size, max_total_size, op_freq)¶

Bases: Abortable

A class that writes binary files for monitoring.

Handles the writing of binary files for monitoring, switching to new files when the current file is full, and deleting old files when the total size of the files exceeds the maximum size.

Parameters:

  • monitor_dir (Path) – The directory to write the binary files to, and continually check size of (deleting oldest files if necessary).

  • max_file_size (int) – The maximum size of each file in bytes. We will write until we have written >= this number of bytes, then switch to the next file. This will not be strictly enforced, as we only check for oversized files at a rate of op_freq Hz.

  • max_total_size (int) – The maximum total size of all files (for this monitor) in bytes. We will delete the oldest file(s) if the total size of all files in the monitor_dir exceeds this value. This will not be strictly enforced, as we only check for oversized files at a rate of op_freq Hz. We will only delete files that we wrote ourselves in this class. We will never delete the currently active file.

  • op_freq (float) – The frequency at which we will check for oversized files and delete old files, in Hz.

class feathersdk.robot.services.data_monitor_service.PerfmonDataWriter¶

Bases: MonitorBinaryFileWriter

Every _thread_step, checks the performance monitor data and writes it

Each perfmon data file will look like:

[header_reserved: uint32_le][header_size: uint32_le][header][chunk_1][chunk_2][…][chunk_n]

Where header is a chunk of header_reserved bytes at the start of the file (after the header_reserved and header_size values), the first header_size bytes of which contains a pickled dictionary mapping string event names to their integer indices.

Each chunk is a chunk of data written each _thread_step of this class containing:

[n_elems: uint32_le][inds: uint16_le * n_elems][times: float32 * n_elems][timestamps: float64 * n_elems]

That is, each chunk starts with the number of elements in the chunk (always > 0), followed by 3 arrays of the same length containing the indices (within the header dictionary) of the event names, the times it took to execute the event, and the timestamps of the event (at the end of the event execution).

NOTE: this class will dynamically update the header when the number of events in the performance monitor changes. It assumes that we can never remove events from the performance monitor.

NOTE: the function execution times are stored as float32. So, we can only exactly store 2**24 - 1 nanoseconds of execution times (~16 milliseconds). However, since python is python, we already don’t actually have nanosecond-level accuracy. In reality, we probably only have on the order of microsecond-level accuracy, in which case we can store ~16 seconds of execution times perfectly. After this, we start to lose precision little by little. I doubt we will ever actually need this level of accuracy, so I’d rather save the space to store more data.

Parameters:

  • monitor_dir (Path) – The directory to write the binary files to, and continually check size of (deleting oldest files if necessary).

  • max_file_size (int) – The maximum size of each file in bytes. We will write until we have written >= this number of bytes, then switch to the next file. This will not be strictly enforced, as we only check for oversized files at a rate of op_freq hz.

  • max_total_size (int) – The maximum total size of all files (for this monitor) in bytes. We will delete the oldest file(s) if the total size of all files in the monitor_dir exceeds this value. This will not be strictly enforced, as we only check for oversized files at a rate of op_freq hz. We will only delete files that we wrote ourselves in this class. We will never delete the currently active file.

  • op_freq (float) – The frequency at which we will write new perfmon data and check for oversized files and delete old files.

  • perf_max_size (int) – The maximum number of performance measurements to store in ring buffer.

class feathersdk.robot.services.data_monitor_service.CandumpDataWriter(monitor_dir, max_file_size, max_total_size, op_freq)¶

Bases: MonitorBinaryFileWriter

Writes candump frames to a binary file as a flat stream of packed CandumpTelemetry entries.

File layout (no headers between batches):

[entry_0][entry_1]…[entry_n]

Each entry is 21 bytes (little-endian, packed), matching Teensy CandumpTelemetry:

[info: uint8][can_id: uint32][data: uint8[8]][timestamp_ns: uint64]

Where info packs: bus (2 bits), sent (1 bit), extended (1 bit), dlc (4 bits), and timestamp_ns is the board-synced monotonic time when the frame was sent or received.

class feathersdk.robot.services.data_monitor_service.TelemetryDataWriter(monitor_dir, max_file_size, max_total_size, op_freq)¶

Bases: MonitorBinaryFileWriter

Writes telemetry batches to a binary file.

File layout (no file-level header; batches concatenated):

[batch_0][batch_1]…[batch_n]

Each batch is:

[f64le timestamp][u16le num_updates][update_0][update_1]…[update_{num_updates-1}]

Where update_i matches Teensy GetTelemetrySingleTelemetryHeader + values:

[u16le telem_idx][u16le n_elems][n_elems * itemsize bytes]

timestamp is host monotonic time when the batch was applied (same epoch as log currtime() / candump after Teensy clock sync). payload is the Teensy body after GetTelemetryPayloadHeader (the num_updates count is stored separately in this batch header, not duplicated inside payload).

Parameters:

class feathersdk.robot.services.data_monitor_service.TeensyMessageDataWriter(monitor_dir, max_file_size, max_total_size, op_freq)¶

Bases: MonitorBinaryFileWriter

Writes teensy host↔board messages to a binary file.

File layout (no file-level header; messages concatenated):

[message_0][message_1]…[message_n]

Each message is:

[f64le timestamp][u8 direction][u32le message_id][u16le opcode][u16le payload_len][payload]

direction is 1 for host→Teensy (sent) and 0 for Teensy→host (received). opcode is the command opcode on TX and the response opcode on RX. payload is the message body only (no ClientCommandHeader).
